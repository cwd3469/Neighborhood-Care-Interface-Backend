## 한 줄 요약

복사해 온 배포 설정이 다른 프로젝트를 가리키고 있었고, EC2 비용이 월 약 19만 원[확인] 나오고 있었다. 포트폴리오 목적에 맞춰 Render(앱) + Neon(DB) 무료 플랜으로 옮겨 **월 비용을 0원**으로 줄였고, 그 대가로 콜드 스타트(첫 요청 약 1분)를 받아들였다.

## 2. 문제

1. **배포 설정이 다른 프로젝트를 가리킴** — `deploy.yml`은 `cd ~/Fhir-Style-Builder`, `docker ps | grep fhir`로, `Jenkinsfile`은 `Fhir-Style-Builder.git`을 clone하도록 되어 있었다. 이 저장소가 원래 FHIR 폼 생성기 프로젝트였고(2026-03 커밋들), 시니어 케어를 같은 저장소에 새로 올리면서(2026-10-16 `first commit`) 설정이 그대로 남은 것. main에 push하면 배포가 실패하거나 엉뚱한 디렉터리를 재빌드할 상태였다.
2. **배포 경로가 두 개** — GitHub Actions와 Jenkins가 같은 일을 각자 하고 있어 어느 쪽이 실제 배포인지 불분명했다.
3. **비용** — EC2가 월 약 19만 원[확인]. 원인: `[직접 채울 것 — 인스턴스 사양/EBS/탄력적 IP 등, Cost Explorer에서 확인한 내용]`
4. **이미지에 넣지 말아야 할 파일이 들어감** — `.dockerignore`가 없어 Mac용 venv(약 125MB)와 `.env`(API 키)가 이미지에 복사되고 있었다.

| 선택지 | 월 비용 | 장점 | 단점 |

## 4. 해결 — 바꾼 것

| 파일 | 변경 | 이유 |
|------|------|------|
| `Dockerfile` | `--port ${PORT:-8000}` | Render는 포트를 `PORT` 환경변수로 준다. 로컬은 8000 그대로 |
| `.dockerignore` (신규) | venv, `.env*`, `*.db`, `.git`, `docs/` 등 제외 | 이미지 크기·비밀값 유출 문제 해결 |
| `main.py` | CORS 허용 주소를 `CORS_ORIGINS` 환경변수에서 읽음 | localhost만 허용하면 Vercel 프론트 요청이 막힘 |
| `database.py` | `pool_pre_ping=True` | Neon이 잠들었다 깨면 끊긴 연결을 재사용해 나는 오류 방지 |
| `.env.example` (신규) | 필요한 환경변수 목록 | 새 환경 세팅 시 참고 |
| `Jenkinsfile`, `deploy.yml` | 삭제 | Render GitHub 연동 자동 배포가 대체 |

## 6. 배운 점

- **복사해 온 설정은 가장 먼저 의심한다.** 코드보다 배포 설정 파일이 프로젝트 이름·경로에 더 강하게 묶여 있다.
- **인프라 선택은 목적에서 시작한다.** "인프라 경험"이 목표였다면 EC2가 맞았고, "데모 링크 유지"가 목표라 관리형 서비스가 맞았다.
- **서버리스 DB는 연결이 끊긴다는 전제로 쓴다** (`pool_pre_ping`).

## 7. 면접용 30초 버전

> 배포 설정을 점검하다 GitHub Actions와 Jenkins가 둘 다 이전 프로젝트 경로를 가리키고 있다는 걸 발견했습니다. 고쳐서 EC2를 유지하는 안과, 관리형 서비스로 옮기는 안을 비용과 목적 기준으로 비교했고, 포트폴리오 데모가 목적이라 Render와 Neon 무료 플랜으로 옮겼습니다. 포트 환경변수화, CORS 환경변수화, Neon 유휴 연결 대비 `pool_pre_ping`, `.dockerignore` 추가가 필요했고, 월 약 19만 원이던 비용이 0원이 됐습니다. 대신 콜드 스타트가 생겨서, 실서비스로 가면 유료 인스턴스로 올리는 게 다음 단계입니다.
