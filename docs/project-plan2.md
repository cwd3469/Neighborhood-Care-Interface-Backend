# 시니어 케어 시스템 — 추가 기능 계획

Oct 16, 2026 · @Caleb

## 핵심 요약

기존 MVP(요양사 기록 → AI 요약 → 보호자 확인)에 **17개 기능**을 더해 "방문 일정 → 방문 → 기록 → 확인" 전체 흐름을 완성한다. 기존 계획 6개는 중복을 합쳐 6개로 정리했고, 필수 7개와 권장 4개를 새로 넣었다.

- **진행 방식:** 4단계로 나눠 단계마다 MVP → 평가 → 평가된 부분만 수정하는 로테이션을 돈다.
- **알림 방식:** 발송 인터페이스(`NotificationSender`)와 Mock 발송을 먼저 만들고, 카카오 알림톡 실발송은 마지막 단계에서 교체한다. 알림톡은 사업자 채널과 템플릿 검수가 필요해 개발과 무관하게 막힐 수 있기 때문이다.
- **일정:** 기존 개발 마감(10/15)이 지났으므로 새 일정이 필요하다. 공수 추정은 4단계 합계 약 6\~8주(하루 1\~2시간 기준, 추정치)다.
- **설계의 중심:** 방문(Visit) 상태 흐름. 알림, 예외, 변경 요청이 모두 이 상태 변화에 얹힌다.

## 역할과 권한

역할은 3종이다. 모든 조회는 "연결된 어르신만"으로 제한한다. 가입은 관리자가 보내는 초대 링크로만 하며, 알림 링크로 들어오는 사용자도 로그인을 거친다.

| 기능 | 관리자 | 요양사 | 보호자 |
| --- | --- | --- | --- |
| 어르신·계약 등록 | 생성·수정 | - | 조회 |
| 사용자 초대 | 보호자·요양사 초대 | - | - |
| 스케줄 편성 | 생성·수정 | 배정된 방문 조회 | 연결된 어르신 조회 |
| 일정 변경 요청 | 승인·반려 | 요청 | 요청 |
| 건강 체크리스트 | 템플릿 관리 + 어르신별 조정 | 조회 | 조회 |
| 보호자 요청 체크리스트 | 대리 작성(보호자 없는 경우) | 조회 | 작성·수정 |
| 요양 기록 | 조회 + 잠금 해제 | 작성·수정(24시간) | 조회 |
| 수정 이력·열람 로그 | 조회 | 본인 기록 이력 조회 | 기록 수정 이력 조회 |
| 대시보드 | 전체 현황 | 오늘 내 방문 | 연결된 어르신 기록 |

한 어르신에 보호자는 여러 명일 수 있다(보호자 N : 어르신 1). 독거 어르신처럼 보호자가 없으면 보호자 권한을 관리자가 대신 행사한다.

## 데이터 모델 초안

## 방문 상태 흐름과 알림 매트릭스

방문(`visit`)은 6가지 상태를 가진다. 알림은 모두 상태가 바뀌는 순간이나 정해진 시각에 나간다. 정상 방문 1건이면 요양사 2건, 보호자 2건으로 총 4건이 발송된다.

| 일정 변경 승인·반려 | 요청자, 보호자, 요양사 | 변경 전후 일시 | F09 |
| 기록 수정(보호자가 이미 열람한 경우) | 보호자 | 수정 안내, 링크 | F13 |

## 비즈니스 규칙

구현 전에 고정해야 할 규칙 12개다. 괄호 안은 관련 기능이다.

1. 요양 기록은 방문 1건당 1개다. 종료 후 24시간이 지나면 잠기고, 잠금 해제는 관리자만 할 수 있다. (F01, F13)
2. 기록을 수정할 때마다 변경 전후 값을 이력으로 남긴다. 보호자가 이미 본 기록이면 "기록 수정됨" 알림을 1회 보낸다. (F13, D6)
3. 기록이 수정되면 AI 요약을 다시 생성한다. (F10)
4. 체크리스트 항목을 수정하거나 삭제해도 과거 기록은 스냅샷 값 그대로 보여준다. 항목 삭제는 `active=false`로 처리한다. (F07)
5. 건강 항목은 관리자 템플릿에서만 만들 수 있다. 보호자는 요청 항목만 만든다. 항목명이 제각각이면 AI 요약과 통계가 깨지기 때문이다. (F07)
6. 건강 항목에 이상치 기준이 있고 입력값이 기준을 넘으면 보호자와 관리자에게 즉시 알림을 보낸다. 기준값 자체(예: 혈압 수치)는 추정으로 정하지 말고 관리자가 어르신별로 입력한다. (F11)
7. 일정 변경은 승인된 순간에만 `visit`에 반영한다. 방문 24시간 전까지만 요청할 수 있고, 1회 변경만 지원한다. (F09, D7, D8)
8. 변경된 시간이 같은 요양사의 다른 방문과 겹치면 관리자 승인 화면에 경고를 표시한다. (F09)
9. 예정 시작 시간에서 15분이 지나도 시작 버튼이 눌리지 않으면 관리자에게 알린다. (F11)
10. 알림 본문에는 이름과 시간만 넣는다. 주소와 건강 내용은 로그인 후 열리는 링크로만 보여준다. 건강정보는 개인정보보호법상 민감정보이기 때문이다. (F03\~F05)
11. 같은 방문에 같은 종류의 알림은 한 번만 보낸다(`idempotency_key` = 방문 ID + 알림 종류). 발송에 실패하면 최대 3회 재시도한다. (F16)
12. 계약이 종료되면 미래 방문을 취소하고 보호자와 요양사의 접근을 차단한다. 기록은 보관한다. 보관 기간은 법적 기준을 확인해야 한다. (F17)

## 범위 제외 항목

아래는 이번 계획에 넣지 않는다. 포트폴리오의 핵심 흐름과 관계가 없거나, 도메인 규정 때문에 범위가 크게 늘어나기 때문이다.

- 요양사 급여 정산, 장기요양 급여 청구
- 보호자와 요양사 간 채팅
- 공단 방문 기록(태그 방식) 연동. 현장에 이미 있는 것으로 알고 있으나 확인이 필요하다
- 바디캠(영상 촬영·확인). 이전에 이미 제외하기로 결정했다
- 반복 규칙 자체에 대한 변경 요청. 관리자가 직접 수정한다

## 단계별 실행 계획

4단계로 나눈다. 각 단계는 끝날 때 평가(요양보호사, 동료, AI)를 받고, 평가된 부분만 고친 뒤 다음 단계로 넘어간다. 공수는 하루 1\~2시간 기준 추정치다.

1. **1단계 — 기록 핵심 흐름** (약 2.5\~3주): F12 역할·초대 → F07 체크리스트 → F08 스케줄 → F01 기록 → F13 잠금·이력 → F10 AI 요약 → F02 보호자 확인
   - 통과 기준: 관리자가 어르신을 등록하면 방문이 생성되고, 요양사가 기록하면 보호자가 요약을 볼 수 있다
2. **2단계 — 알림 파이프라인(Mock 발송)** (약 1\~1.5주): `NotificationSender` 인터페이스와 `MockSender`, 스케줄러(APScheduler 등 1개 선택) → F03 → F04 → F05 → F06
   - 통과 기준: 방문 1건에 대해 알림 5종이 정해진 시점에 한 번씩만 기록된다
3. **3단계 — 변경과 예외** (약 1.5주): F09 일정 변경 요청·승인 → F11 예외 처리, 일회성 요청 체크리스트(D3)
   - 통과 기준: 변경 승인, 미실시, 이상치가 모두 알림과 대시보드에 반영된다
4. **4단계 — 운영 품질과 실발송** (약 1\~2주): F14 대시보드 → F15 동의·열람 로그 → F16 수신 설정·재시도 → F17 계약 종료 → 카카오 알림톡 실발송 교체(가능한 경우)
   - 통과 기준: 포트폴리오 배포 후 시연 시나리오 1개가 처음부터 끝까지 동작한다

## 리스크와 반대 관점

가장 큰 리스크는 범위다. 기능이 17개로 늘면서 기존 MVP의 "기록 → AI 요약" 차별점이 평범한 업무 시스템 안에 묻힐 수 있다.

| 리스크 | 실패 시나리오 | 대응 |
| --- | --- | --- |
| 범위 폭발 | 4단계까지 끝내지 못하고 구직 시점이 밀린다 | 1\~2단계만 끝내도 포트폴리오로 쓸 수 있게 만든다. 3\~4단계는 선택 항목으로 둔다 |
| 차별점 희석 | 면접관에게 "일반적인 CRUD + 알림 앱"으로 보인다 | AI 요약, 스냅샷, 중복 발송 방지 같은 설계 근거를 README 앞쪽에 둔다 |
| 알림톡 실발송 불가 | 사업자 채널이나 템플릿 검수 때문에 실제 발송을 못 한다 | Mock 발송과 발송 내역 화면으로 시연한다. 교체 가능한 구조 자체를 어필한다 |
| 현장과의 이중 입력 | 요양보호사 평가자가 "공단 앱과 중복"이라고 평가한다 | 1단계 평가 때 시작·종료 버튼이 부담인지 먼저 확인한다 |
| 민감정보 처리 | 알림 본문이나 로그에 건강정보가 노출된다 | 규칙 10번(본문 최소화)을 1단계부터 적용한다 |
| 알림 피로 | 하루 4곳을 방문하는 요양사가 알림을 대략 8건 받아 무시하게 된다 | F16 수신 설정을 넣고, 평가 때 알림 수가 적절한지 확인한다 |

**반대 관점:** 포트폴리오 관점에서는 기능 수보다 "하나를 깊게 풀었다"는 증거가 더 강하다. 그렇게 보면 1단계 + F10(AI 요약)을 깊게 다듬고 알림은 설계 문서로만 남기는 선택도 합리적이다. 2단계를 끝낸 뒤 시점에서 계속 진행할지 다시 판단한다.
