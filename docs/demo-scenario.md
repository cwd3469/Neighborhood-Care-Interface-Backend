# 데모 시나리오 + 테스트 계정

> 상태: **초안** — `[직접 채울 것]`을 채우고, 운영 화면에서 한 번 리허설한 뒤 이 줄을 지운다.
> 모든 데이터는 더미다. 실제 개인정보·건강정보를 넣지 않는다 (서버가 해외 리전).

## 0. 데모 링크·계정

| 항목 | 값 |
|------|----|
| 서비스 주소 | `[직접 채울 것 — Vercel 주소]` |
| API 문서 | `[직접 채울 것 — Render 주소]/docs` |
| 요양사 | `demo_caregiver` / `[비밀번호 — 이력서·지원서에만 적기]` |
| 보호자 | `demo_guardian` / 같은 비밀번호 |
| 관리자 | 공개하지 않음 (데이터를 지울 수 있음) |

### 데이터 만들기 (처음 한 번)

```bash
cd backend
DATABASE_URL='<Neon 주소>' python scripts/create_admin.py   # 관리자가 없을 때만
DATABASE_URL='<Neon 주소>' python scripts/seed_demo.py      # 데모 계정·데이터
```

`seed_demo.py`가 만드는 것:

| 대상 | 내용 |
|------|------|
| 요양사 이미영 (`demo_caregiver`) | 아래 일정 5건 전부 담당 |
| 보호자 김지훈 (`demo_guardian`) | 김순자 어르신과만 연결 |
| 김순자 어르신 | 과거 방문 3건 + 기록 3건 (정상 / 혈압 상승 162/98 / 발열 38.2℃·SpO₂ 92%), 오늘 14:00 일정 1건 |
| 박영호 어르신 | 오늘 10:00 일정 1건, **보호자와 연결 안 됨** (권한 데모용) |

AI 요약은 미리 만들지 않는다. 데모에서 처음 생성되는 장면을 보여주기 위해서다.
같은 날 데모를 다시 하려면 오늘 일정 상태가 이미 '완료'일 수 있다 — 관리자 화면에서 새 일정을 하나 추가한다.

## 1. 데모 전 준비 (5분 전)

1. **서버 깨우기** — Render 무료 인스턴스는 15분 동안 요청이 없으면 잠들고, 깨어나는 데 약 1분이 걸린다. `API 문서` 주소를 먼저 한 번 열어 둔다.
2. 브라우저 창 2개: 일반 창(요양사), 시크릿 창(보호자). 쿠키가 섞이지 않게 하기 위해서다.
3. 면접관에게 직접 눌러 보게 할 때는 이렇게 안내한다: "첫 접속은 서버가 깨어나느라 1분 정도 걸릴 수 있습니다."

## 2. 시나리오 (약 5분)

### 장면 1 — 요양사: 방문 진행 + 기록 (1분 30초)

| # | 화면 | 동작 | 말할 포인트 |
|---|------|------|-------------|
| 1 | `/login` | `demo_caregiver` 로그인 | 역할에 따라 `/caregiver`로 이동한다. 토큰은 httpOnly 쿠키에 있어서 JS로 읽을 수 없다 |
| 2 | 오늘 방문 일정 | 김순자 14:00 카드에서 **방문 시작 → 방문 완료** | 상태 변경은 담당 요양사와 관리자만 할 수 있다 |
| 3 | 같은 카드 | 기록 폼에 메모 입력 후 저장 | 메모 예: "점심 식사 절반 섭취. 오후에 어지러움 호소, 10분 휴식 후 호전." |
| 4 | 담당 어르신 목록 | 김순자·박영호 2명 | 일정이 잡힌 어르신만 담당으로 본다 (일정 기반 담당) |

### 장면 2 — 보호자: 확인 + AI 요약 (2분)

| # | 화면 | 동작 | 말할 포인트 |
|---|------|------|-------------|
| 5 | `/login` (시크릿 창) | `demo_guardian` 로그인 | |
| 6 | 대시보드 | 김순자만 보임 | 박영호는 연결된 보호자가 아니라 목록에서 빠진다 |
| 7 | 김순자 상세 | 활력징후 패널 | 혈압 162/98, 체온 38.2℃가 수치로 쌓여 있다. FHIR 원본에서 LOINC 코드로 꺼내 저장한 값이다 |
| 8 | 건강기록 조회 | 4일 전 기록(혈압 상승)에서 **AI 요약** 열기 | 처음 열 때만 Claude를 부르고, 그다음부터는 DB에 저장된 요약을 보여준다 |
| 9 | 같은 화면 | 이상징후 배지 확인 | 혈압 초과·복약 누락 의심이 배지로 표시된다 (생성 문장은 매번 조금씩 다름) |

### 장면 3 — 권한 (1분)

| # | 동작 | 기대 결과 | 말할 포인트 |
|---|------|-----------|-------------|
| 10 | 보호자 창 주소창에서 `/guardian/<박영호 id>` 직접 입력 | 접근 권한 없음 화면 (403) | id만 바꿔 남의 데이터를 보던 IDOR을 막았다. 권한 테스트 35개로 고정 |
| 11 | (선택) API 문서에서 보호자 토큰으로 `GET /records/{박영호 기록}` | 403 | 화면이 아니라 서버가 막는다 |

박영호 id는 `seed_demo.py` 실행 결과에 출력된다: `[직접 채울 것]`

### 마무리 멘트 (30초)

> 요양사가 기록하면 FHIR 형식으로 저장되고, 활력징후는 LOINC 코드로 따로 정리됩니다. 보호자는 연결된 어르신만 볼 수 있고, AI 요약은 이상 수치와 메모를 함께 보고 이상징후를 표시합니다. 권한은 서버에서 검사하고 회귀 테스트로 고정했습니다.

## 3. 데모에서 피할 것 (알려진 한계)

| 항목 | 현재 상태 | 데모에서 |
|------|-----------|----------|
| 회원가입 화면 (`/signup`) | web이 백엔드에 없는 주소(`/api/v1/auth/signup`)를 부른다 → 가입 실패 | 보여주지 않는다. 계정은 관리자가 만든다고 설명 |
| 요양사 화면에서 활력징후 입력 | 기록 폼은 메모만 받는다 (`fhir_response`가 빈 값) | 장면 1의 기록에는 수치가 없다. 수치 데모는 미리 넣어 둔 과거 기록으로 |
| 콜드 스타트 | 첫 요청 약 1분 | 1번 준비 단계에서 미리 깨운다 |
| AI 요약 문장 | 매번 다름 | 특정 문장을 약속하지 않는다 |
