# 시니어 케어 프로젝트

## 1. 프로젝트 개요

**"우리 동네 시니어 케어 매니저"** — 고령화 사회를 반영한 방문요양·건강기록 관리 SaaS

- 보호자 / 요양사 / 관리자 3개 역할, 각기 다른 대시보드
- 방문 일정 매칭 및 관리 (ERP에서 다룬 업무 로직 재사용 포인트)
- 건강기록 CRUD 및 이력 조회 — **FHIR 표준 기반**: 방문 기록은 FHIR `QuestionnaireResponse` 리소스(JSONB)로 원본 저장, 혈압·맥박 등 핵심 수치는 FHIR `Observation` 구조(LOINC 코드)로 추출해 별도 테이블에 구조화 저장 (대시보드 쿼리/추이 그래프용)
- AI 기능: 방문 기록 텍스트를 요약·이상징후 하이라이트 (LLM API 연동)
## 2. 기술 스택 (기본값, 사용자가 다른 요청 시 우선)

- 프론트: Next.js + TypeScript (기존 강점 유지, App Router)
- 백엔드: **파이썬 (FastAPI)** ← 확정
- 인증: NextAuth 또는 자체 JWT 구현 (학습 목적상 한 번은 직접 구현 권장)
- 배포: Vercel(프론트) + Railway/Render(백엔드)
- 헬스케어 데이터: FHIR 리소스(QuestionnaireResponse, Observation)를 다루므로 관련 응답/설명 시 FHIR 스펙 기준으로 정확하게 안내할 것 (사용자가 FHIR 문진 제작 경험 보유)
## 3. AI 코딩 도구 사용 원칙

프로젝트 구현 과정에서 AI 코딩 도구(Claude Code 등)를 쓰되, 범위를 다음과 같이 제한한다.

- **AI에게 맡기는 것**: 반복적인 보일러플레이트 — CRUD 엔드포인트 뼈대, DB 마이그레이션 파일, 기본 DTO/스키마 정의
- **직접 구현하는 것**: 인증/인가 로직, FHIR Observation 매핑, 건강기록 관련 트랜잭션 등 핵심 도메인 로직 — 아래 4번 "Claude가 응답할 때 지켜야 할 것"의 TODO 방식 그대로 유지
  이 구분을 두는 이유:
- 헬스케어 도메인 특성상 "왜 이렇게 설계했는지" 설명 못 하면 포트폴리오 어필력이 떨어짐
- AI 도구로 절약한 시간은 5번 마일스톤(AI 요약 기능, 실제 AI 에이전트 역량 학습 포인트)에 재투자
## 4. Claude가 응답할 때 지켜야 할 것

- **프론트 관련 설명은 짧게.** 이미 5년차 실력이므로 기초 설명 생략, 바로 실전 패턴 위주로.
- **백엔드/인프라 개념은 원리부터.** 왜 이렇게 설계하는지(계층 분리, DTO, 트랜잭션, 인덱싱 등) 근거를 짚어줄 것.
- 코드를 통째로 던지지 말고, **직접 채워야 할 부분은 TODO로 남겨** 이해하고 넘어가게 할 것 (단, 사용자가 "그냥 완성본 줘"라고 명시하면 예외).
- 매 기능 구현 후 **실무 관점 피드백**(이력서/포트폴리오에 어떻게 어필할지) 한두 줄 덧붙이기.
- 헬스케어/개인정보 도메인이므로 **인증·인가, 데이터 암호화, 로깅** 관련해서는 실제 서비스 수준의 관례를 알려줄 것.
- AI 기능 구현 시 Anthropic API 연동 방법은 product-self-knowledge 기준 최신 정보로 안내.
